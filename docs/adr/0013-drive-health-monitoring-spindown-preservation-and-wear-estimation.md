# Drive Health Monitoring, Spin-Down Preservation, and Wear Estimation

To monitor storage reliability and remaining lifespan without spinning up mechanical hard drives or weakening container isolation, Arkive adopts an unprivileged host-side telemetry exporter coupled with SSD-tier metric caching. The host operating system runs a lightweight periodic probe (every 15 minutes) using `smartctl -a -j -n standby` against persistent block device paths (`/dev/disk/by-id/`). If the secondary mechanical hard drive is spun down, `smartctl` exits immediately via the ATA `CHECK POWER MODE` register, writing an atomic JSON status snapshot (`/var/run/arkive/smart.json`) to the root SSD (`/`). The containerized Go application mounts this directory read-only (`:ro`), requiring zero raw block device mounts and no `CAP_SYS_RAWIO` capability, upholding ADR-0009. Fresh telemetry is persisted to PostgreSQL and cached in Valkey on the SSD, and opportunistic refresh hooks capture full S.M.A.R.T. updates during scheduled operations such as upload streams and the 03:00 AM database backup worker. Drive health is evaluated against a deterministic three-tier model: Healthy, Warning (reallocated sectors 1 to 49, load cycles >= 300,000, temperature >= 50°C, or SSD wear >= 80%), and Critical (pending sectors > 0, uncorrectable sectors > 0, reallocations >= 50, or SSD wear >= 100%). In the Admin dashboard, cryptic raw attribute tables are hidden behind an expandable drawer; primary cards surface human-readable operational age ("Used for 3 years, 7 months"), drive spin state ("Sleeping" vs "Active"), temperature alerts, and plain-English recovery guidance linking directly to backup workflows.
