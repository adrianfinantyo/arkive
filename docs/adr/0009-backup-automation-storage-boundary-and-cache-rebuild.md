# Backup Automation, Host Storage Boundary, and Disaster Recovery Cache Rebuild

To provide robust disaster recovery without complicating container permissions or wasting backup bandwidth, Arkive delegates disk pooling and array redundancy (e.g. SnapRAID, mergerfs, mdadm) to the host operating system. The application operates strictly against standard filesystem mount paths, querying storage telemetry via non-waking `statvfs` system calls. Offsite backups are automated via an off-peak Asynq cron worker (03:00 AM) that generates an atomic database snapshot to `/mnt/storage/backups/` with a rolling 7-day retention window, subsequently triggering an optional offsite sync command (such as `rclone sync`). Ephemeral assets, including the SSD Preview Cache and temporary upload staging files, are excluded from backups to minimize cloud storage footprint. For disaster recovery scenarios where original media and database records are restored but the SSD cache is empty, Arkive provides an `arkive cache rebuild` CLI routine and Admin dashboard trigger that scans for missing previews and queues generation tasks into the background worker on Core 1 (`nice -n 19`, `ionice -c 3`) without degrading host responsiveness.
