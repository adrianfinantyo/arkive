# On-the-Fly Streaming Zip Archives and Dual-Tier Path Routing

To generate multi-gigabyte batch and album zip downloads on low-power hardware (Intel Pentium E5400, 3.8GB RAM) without disk spooling or RAM bloat, Arkive streams zip archives directly from disk to the HTTP response using Go's `archive/zip` in Store mode (compression method 0). Store mode eliminates Deflate CPU overhead on Core 0, relying on pure sequential I/O with standard data descriptors (bit 3) and pooled 64KB buffers (`sync.Pool`) to keep stream heap memory under 100KB. File path routing is dual-tiered based on requested quality: `optimized` downloads resolve 100% of photo assets to pre-generated JPEG previews in the SSD Preview Cache (`/var/cache/arkive/previews/`), preserving mechanical HDD spin-down indefinitely; `original` downloads pull raw media from the Raw Media Store (`/mnt/storage/library/`), absorbing spin-up latency via UI status indicators and acquiring a slot from a 2-stream disk read semaphore to prevent head thrashing. All authorizations, file counts (capped at 1,000 files), total size limits (capped at 10GB), and video guardrails (capped at 1GB per video) are validated against database metadata before sending HTTP 200 headers. If a client disconnects or an I/O read fails mid-stream, `http.Request.Context().Done()` halts reading, closes the active file descriptor immediately, releases the disk read semaphore via `defer`, and truncates the stream without an End of Central Directory record so client extractors cleanly detect incomplete transfers.
