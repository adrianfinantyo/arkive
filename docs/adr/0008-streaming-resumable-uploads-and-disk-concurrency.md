# Streaming Resumable Uploads and Disk Concurrency Controls

To support reliable multi-gigabyte media uploads on low-power hardware without RAM bloat, Arkive implements the open `tus` v1.0 resumable upload protocol using a bespoke Go HTTP handler. Request streams write directly into `/mnt/storage/.staging/` using 64KB pooled buffers (`sync.Pool`), completely bypassing temporary buffering on the root SSD (`/tmp`). To protect the single mechanical hard drive from head thrashing and throughput collapse under concurrent multi-user load, active disk writes are capped at 2 concurrent streams via a Go semaphore with fair per-chunk round-robin scheduling, and contiguous blocks are pre-allocated upfront via `fallocate()`. Concurrent video streaming requests from the storage drive are prioritized over background upload writes via the Linux `mq-deadline` scheduler, served in 2MB read-ahead chunks, and bounded to a maximum of 5 simultaneous streams. Completed uploads promote to the media library via an atomic, zero-copy `os.Rename`, immediately triggering an eager background thumbnail job via Valkey/Asynq while the hard drive is already active.
