# Docker Compose Deployment with PostgreSQL and Redis

Arkive was initially planned around an embedded single-binary architecture with SQLite. The deployment strategy was updated to adopt a containerized Docker Compose stack incorporating PostgreSQL (for relational data) and Redis (for sessions, caching, and task queuing). While this increases stack idle memory from ~15MB to ~120–150MB (acceptable on the 3.8GB host), it provides enterprise-grade data integrity, native concurrent connection pooling, and standard Redis-backed asynchronous worker queues (`asynq`). To preserve the primary system invariants (<100MB idle RAM for the Go service, HDD drive spin-down, and low CPU overhead on Pentium E5400), PostgreSQL and Redis are tuned with minimal memory profiles (`shared_buffers = 32MB`, Redis `maxmemory 32MB`) and their container volumes reside exclusively on the SSD (`/`), isolating the mechanical HDD (`/mnt/storage`) exclusively for raw media.
